AS 접수 현황 · 개선 근거와 확인 사항

현재 프로젝트의 실제 AS 현황 화면과 동일한 예시 70건을 사용한 별도 HTML입니다. 실제 메뉴, 업무 용어, 접수 목록 연결, 월 선택, 금액 집계를 보존합니다. 운영 화면에 시안을 자동 적용하지 않습니다.

현재 UI·UX 문제

  • 전체 대기와 단계별 수치가 같은 카드 위계여서 전체와 부분의 관계가 불분명합니다. 전체를 구분하고 단계 합계 식과 ‘목록 보기’를 함께 표시합니다.
  • 상단은 전체 기간의 현재 상태, 하단은 선택 연도의 접수일 기준인데 범위 차이가 잘 드러나지 않습니다. 영역별 기준을 명시합니다.
  • 같은 월별 수치에 막대·선·평균선이 중복됩니다. 공통 기준선에서 높이를 비교하는 단일 막대를 선택합니다. 평균은 미도래 월 처리 기준이 정해지기 전까지 생략합니다.
  • 도넛의 면적과 떨어진 라벨을 오가야 해서 유형 간 비교가 느립니다. 2~5안은 내림차순 가로 막대를 사용하고 정확한 건수·비율을 같은 행에 둡니다. 1안은 최소 변경을 비교하기 위해 도넛을 유지합니다.
  • 0건 유형은 기본으로 접어 실제 자료가 있는 항목을 먼저 봅니다. 펼치면 모든 유형을 확인할 수 있습니다.

데이터 표시상 확인 사항

항목확인된 동작시안 처리 / 추가 확인
전체 대기현재 상태가 ‘완료’가 아닌 전체 접수입니다. 연도 필터의 적용 대상이 아닙니다.단계별 합계와 다른 상태가 있으면 ‘기타 상태’를 별도로 표기합니다. 미분류 상태의 업무 의미는 확인이 필요합니다.
0건·미집계API에는 집계 완료일·데이터 수집 범위가 없습니다.과거 빈 월은 ‘0* 조회 자료 없음’, 미래 빈 월은 ‘— 미도래’로 구분합니다. 실제 확정 0건과 미집계의 자동 구분은 보류합니다.
기준일·시간대화면의 기준일은 HTML 생성 시 한국 날짜입니다. 서버 데이터 동기화 시각은 제공되지 않습니다. 현재 집계 코드는 createdAt 문자열의 날짜 부분을 사용합니다.기준일은 데이터 마감일이 아닙니다. 운영 전 접수일의 한국 시간 변환 기준과 집계 마감 메타데이터를 확인해야 합니다.
전월 대비선택 월 조회 건수와 전월 전체 조회 건수를 비교합니다.이번 달은 ‘일부 기간 ↔ 전월 전체’를 명시합니다. 동일 경과일 비교와 마감 월 비교 중 업무 기준 확정이 필요합니다. 전월 0건이면 증감률을 만들지 않습니다.
유형 분류고정 사유 7개와 정확히 일치하지 않으면 ‘기타’입니다. 현재 예시 70건은 자유 입력 문구여서 모두 기타로 집계됩니다.보기 좋은 분포를 만들기 위해 수치를 바꾸지 않습니다. 정상 기타와 분류 누락을 구분할 코드·사유 필드 분리 여부를 확인합니다.
금액입력된 원 단위 정수를 접수 월별로 합산하며 빈 값은 제외합니다.미입력 건수와 입력 0원을 구분합니다. 매출·입금 월별 실적이라는 의미로 바꾸지 않습니다. 취소·환불·부가세 포함 여부는 별도 확인 사항입니다.
완료·미완료각 월에 접수된 건의 현재 상태로 계산합니다.해당 월말 당시 잔량 또는 그 달의 완료 실적이 아닙니다. 과거 시점의 잔량은 상태 이력 집계가 필요합니다.

배치와 업무 흐름

전체·단계별 대기 확인 → 카드 클릭으로 해당 접수 목록 조회 → 연도·월 선택 → 전월과 유형별 비교 → 금액 미입력·기타 분류 확인 순서입니다. 대기 건수는 연도와 독립적인 전체 기간이라는 설명을 유지합니다.

월별 원장 열은 월 / 접수(건) / 완료(건) / 미완료(건) / 금액(원)입니다. 숫자는 오른쪽 정렬, 천 단위 쉼표, 원 단위 정수로 통일합니다. 상태 원장을 추가 편집하는 대신 기존 접수 목록의 수정 기능을 사용합니다.

5개 시안

  1. 기존 배치 정돈 — 도넛 포함, 최소 변경 비교용.
  2. 추이 집중형 — 월별 차트를 넓게 배치, 연간 흐름 확인용.
  3. 업무 비교형 · 추천 — 월별 접수와 유형 순위를 나란히 비교, 매일 사용하는 현황 화면에 적합.
  4. 월별 가로 비교표 — 엑셀처럼 월별 정확한 값 대조에 적합.
  5. 확인 사항·원장형 — 금액 미입력·기타 분류 확인과 월별 원장을 함께 배치.

공통 디자인 기준과 상태

본문 15px, 제목 18px, 대기 수치 28px. Pretendard와 맑은 고딕 대체 글꼴, 고정 폭 숫자, 진한 본문과 분명한 경계선을 사용합니다. 선택 월만 절제된 청색으로 강조하고 미래는 무늬·텍스트를 함께 사용합니다. 기본 브라우저 키보드 동작과 명확한 포커스를 유지합니다.

각 시안의 ‘화면 상태’에서 로딩·데이터 없음·조회 오류를 확인할 수 있습니다. 조회 오류를 0건으로 표시하지 않습니다. 현재 연도·선택 월은 계속 표시되며 ‘선택 초기화’로 기준일의 월로 돌아옵니다. 기간에 자료가 없으면 도넛과 전월 증감으로 실적을 단정하지 않습니다.

추가 반영 제안

  • 접수일·최종 갱신 시각·집계 완료일까지 제공해 실제 0건 / 수집 전 / 조회 실패를 구분합니다.
  • 기타 유형의 원문 사유를 확인할 수 있는 상세 목록과 유형 코드 정규화를 검토합니다.
  • 금액 미입력 목록 연결과 동일 경과일 전월 비교를 다음 개선 후보로 둡니다.
  • 이상 상황 경보는 담당자·납기·단계별 체류일과 기준을 확정한 뒤 추가합니다. 단순 접수 증가를 지연이나 장애로 단정하지 않습니다.

시안에서는 기존 수치를 유지했습니다. 자료 완전성, 업무상 이상 기준, 금액의 회계적 의미가 정해지기 전에는 경고 등급이나 성과 지표를 임의로 만들지 않습니다.
