# AS 요청 업체 적용 계획

**Goal:** 승인된 1안처럼 실제 접수 기본 정보 맨 위에 요청 업체 입력칸을 배치하고 안내 문구를 제거한다.
**Architecture:** 기존 HTML·3단계 접수 UI와 JSON 서비스의 선택 문자열 필드를 사용한다. PostgreSQL 스키마 변경과 신규 의존성은 없다.
**Tech Stack:** HTML, JavaScript, Express, node:test, Playwright.

## 범위와 결정

- 요청 업체는 `requestingCompany`, 최대 100자, 선택 입력으로 저장한다. 기존 접수 및 구버전 클라이언트와 호환한다.
- 기본 정보 첫 칸에 배치하고 시안 전환·저장 차단·추가 안내 문구를 제거한다.
- 신규/수정/새 접수 초기화, 전체 검색, 접수서 출력에서 값을 연결한다. 출력은 기존 HTML escaping을 사용한다.
- 사용자 작업인 `design-previews/`와 업무 데이터는 커밋하지 않는다.
- 작업 브랜치를 게시하고 PR 전체 diff 및 호출부를 리뷰한다. AGENTS.md에 따라 해당 PR의 병합 승인을 확인한다.

## Review Focus

- 구버전 접수와 요청 업체가 없는 요청은 기존 동작을 유지해야 한다.
- 부분 수정은 기존 업체명을 지우지 않아야 한다.
- 잘못된 타입·길이·제어문자는 저장되면 안 된다.
- HTML 형태 업체명은 출력 시 실행되지 않아야 한다.
- 시안 URL을 사용해도 검증을 건너뛰거나 저장이 차단되면 안 된다.

## 검증 기록

- 신규·수정 multipart 요청과 실제 JSON 저장값, 업체명 초기화, 모바일 배치, 출력 escaping을 검증했다.
- 별도 리뷰에서 API·저장소·워크플로 호출부를 확인하고 차단 결함이 없었다. 리뷰어의 서비스 검사 20개도 통과했다.
- 수정 브라우저 검사는 기존 처리 완료 modal 알림이 닫힌 뒤 입력하도록 고쳤다. 제품 코드의 알림 동작은 바꾸지 않았다.
- 최신 main의 첨부파일 목록 변경을 통합했다. 파일명 안전성 검사의 DOM 경로를 새 목록 구조에 맞췄으며, 기존 파일명 텍스트 처리 검증은 유지했다.
