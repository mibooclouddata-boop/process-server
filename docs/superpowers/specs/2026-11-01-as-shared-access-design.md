# AS 공동 작업 권한과 비활성 계정 생성

사용자가 2026-11-01 승인한 정책: 로그인한 모든 활성 직원이 다른 직원의 AS도 조회, 등록, 수정, 진행 변경, 첨부 관리, 삭제, 복원, 이력 확인할 수 있다. AS 검토·승인 권한은 사용하지 않으므로 제거한다.

## 선택한 방식
- 작성자 제한 유지보다 모든 직원 공동 작업을 선택했다. 모든 직원에게 두 권한을 강제로 부여하는 방식 대신 불필요한 권한 판단과 설정을 제거한다.
- 로그인, 활성 계정, 시스템 관리자 전용 사용자 관리, 버전 충돌, 요청 중복 방지, 삭제·복원 사유 및 작업자 이력은 유지한다.
- 화면의 AS 권한 탭과 권한 해제 버튼을 제거한다. 실제 단계별 완료자 표시인 출력 문서의 결재선은 권한 설정과 별개이므로 보존한다.
- Supabase는 새 마이그레이션으로 첨부 정책의 관리 함수만 공동 작업 기준으로 바꾼다. 기존 마이그레이션과 과거 데이터·권한 열은 복구 호환성을 위해 보존하고 앱에서 사용하지 않는다. 실제 DB 적용은 하지 않는다.
- 로컬 신규 사용자 생성은 active:false를 보존하고 생략 시 true로 명시한다.
- ID 재사용은 이번 정책에서 AS 권한 우회가 아니다. 계정 식별자 구조 변경, PDF/이력 자원 제한, 공급자 인증 경합은 별도 검증 사항으로 남긴다.

## 검증 및 범위
더미 데이터와 임시 디렉터리, 로컬 HTTP와 인메모리 PostgreSQL로 변경 동작을 검사한다. 실제 운영 서버·Supabase·업무 데이터·비밀키는 사용하지 않는다. 기존 감사의 미확정 항목 전체를 재현했다고 주장하지 않는다. 커밋·푸시·PR·운영 배포는 하지 않는다.
