# 로그인 성공 교차 페이드

사용자는 다섯 HTML 시안을 비교한 뒤 교차 페이드의 실제 적용과 Git 게시를 승인했다.

- 기존 MIBOO 색상, 화면 구조와 기술을 유지한다. 새 라이브러리는 추가하지 않는다.
- 로그인 성공 시 인사말이 360ms 동안 나타나고, 1,250ms 읽기 시간을 준다. 준비된 업무 화면과 약 420ms 교차 페이드한다.
- 로그인과 메인의 바탕을 동일하게 유지한다. 다음 화면의 인증과 초기 A/S 조회가 끝나기 전까지 덮개를 유지한다.
- 8초 응답 제한과 오류 안내, 재시도 및 로그인 복귀를 제공한다. 실패 재시도에는 인사말을 반복하지 않는다.
- 성공 직후의 페이지 이동에만 일회성 전환 상태를 전달한다. 새로고침, 일반 이동과 브라우저 뒤로 복귀에서는 인사말을 반복하지 않는다.
- 모션 감소에서는 이동과 애니메이션을 생략하되 읽기 시간을 유지한다. 준비 중 업무 화면의 키보드 접근을 차단하고 완료 시 제목으로 포커스를 옮긴다.

## 비교한 방식과 선택

교차 페이드, 짧은 상향 전환, 배경 드러내기, 제목 정렬, 간결한 페이드 중 사용자가 교차 페이드를 선택했다. 공간 이동이 없어 업무 시스템에 가장 절제된 안이다.

공통 CSS/JS가 로그인 페이지 안의 동일 출처 프레임에서 실제 대시보드를 준비한다. 인증 판단은 기존 서버 세션을 사용하고, 대시보드는 초기 데이터 렌더 완료를 부모 전환 모듈에 알린다. 완료하면 URL을 /dashboard.html로 바꾸며 새로고침은 원래 대시보드에 직접 진입한다. 인사말 재생 여부를 저장소에 보관하지 않는다.

초기에는 일회성 상태를 전달하는 일반 문서 이동을 구현했으나, 독립 리뷰에서 HEAD 200 이후 실제 GET 503이 발생하면 원본 오류 복구 UI를 잃는 문제가 재현되었다. 이를 해결하기 위해 검증된 메인 문서를 그대로 드러내는 프레임 방식으로 변경했다. 프레임은 실제 문서와 데이터가 준비되기 전까지 비활성화되며, 오류·재시도 때 제거하여 오래된 응답을 격리한다. 뒤로가기와 로그아웃 경로도 검증한다.

데이터 저장·DB 스키마·권한·배포 설정은 변경하지 않는다. 작업 브랜치 푸시 및 초안 PR까지 진행하고, 병합과 배포는 별도 승인이 필요하다.
